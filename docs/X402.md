# x402 paywall — agents pay per call, no account needed

The engine can charge for its metered endpoints over **x402 v2** — the
HTTP-native payment standard that has processed 165M+ agent transactions,
~98.6% in USDC, at a sub-$0.31 average. A caller with a funded wallet pays
per call; a caller with an engine API key uses the account path and pays
nothing per call (the existing key/quota metering applies).

## What is charged

| Route | Price key | Default (USDC) |
|---|---|---|
| `POST /audit/quick` | `audit_quick` | $0.02 |
| `POST /audit/run` | `audit_full` | $0.10 |
| `POST /dcm/infer` | `dcm_infer` | $0.001 |

Everything else (reports, monitors, DCM/MeshPay reads, MCP) is free or
key-metered. Disabled by default; `JAMBU_X402_ENABLED=1` turns it on.

## The flow (spec-exact)

```
client ── POST /audit/quick ─────────────────────────────► 402
        ◄── PAYMENT-REQUIRED: base64(PaymentRequired) ────
            { x402Version: 2, resource: {...},
              accepts: [{ scheme: "exact", network: "eip155:84532",
                          amount: "20000", asset: "0x…USDC",
                          payTo: "0x…", maxTimeoutSeconds: 60,
                          extra: { name: "USDC", version: "2" } }] }

client ── POST /audit/quick ──► PAYMENT-SIGNATURE: base64(PaymentPayload)
        ◄── 200 + SSE audit stream   (buffered responses also carry
                                      PAYMENT-RESPONSE with the settlement)
```

Implementation notes that matter:

- **Authorization flow** (verify → resource → settle → respond). The audit
  streams *before* settlement; payments settle when the body completes,
  and every settlement (or skip/failure) is recorded as a receipt.
- **`PAYMENT-RESPONSE`** is delivered on buffered responses. An SSE stream
  has already sent its headers, so settlement for streams is recorded in
  `GET /x402/receipts` instead — intentional, and documented for clients.
- **Non-2xx responses are not settled** (`error_skipped` receipts): the
  authorization is verified, but no funds move for failed work.
- **Replay protection**: a settled nonce cannot be reused (server-side
  guard, on top of EIP-3009's on-chain nonce).
- **Fail closed**: enabled without `JAMBU_X402_PAY_TO` → 503, never free
  paid work.

## Run it

```bash
# Test everything offline with the mock facilitator (never touches a chain)
export JAMBU_X402_ENABLED=1
export JAMBU_X402_PAY_TO=0xYourReceivingAddress
uvicorn backend.engine:app --port 8001

curl -s localhost:8001/x402/config | jq .
curl -si -X POST localhost:8001/audit/quick \
     -H 'Content-Type: application/json' \
     -d '{"url":"https://example.com"}' | head -3   # → 402 + PAYMENT-REQUIRED
curl -s localhost:8001/x402/receipts | jq .        # settled receipts
curl -s localhost:8001/x402/receipts/root | jq .   # Merkle root (MeshPay anchor payload)
```

Real settlement (USDC on Base by default):

```bash
export JAMBU_X402_NETWORK=eip155:8453        # Base mainnet (84532 = Sepolia)
export JAMBU_X402_ASSET=0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913  # USDC on Base
export JAMBU_X402_FACILITATOR=https://<facilitator-host>   # implements /verify + /settle
```

`/x402/config` reports `facilitator_mode` (`mock` vs `http`) so no client
can mistake a demo for a chain.

## Receipts → MeshPay

Each settled receipt stores a canonical `receipt_hash`
(JS-faithful serialization, same verifier discipline as MeshPay).
`GET /x402/receipts/root` returns the Merkle root over the receipt window —
exactly the payload shape MeshPay anchors. Wiring that root into
`/meshpay/anchor` epochs is the next step on the roadmap.

## Client side

Any x402 client works: send the 402's `accepts[0]`, sign an EIP-3009
authorization, retry with `PAYMENT-SIGNATURE`. For tests and demos, a
payload with `authorization.nonce` starting with `mock-` is accepted by the
mock facilitator — and by nothing else.
